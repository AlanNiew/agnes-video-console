# 从 0 到 1 创作实战手册（Creation Playbook）

> 基于 v2.0.3 全流程实拍《末班车》的复盘。用途：再次从 0 到 1 创作视频前**先读这份**——实测 SOP、踩过的坑、成片自检清单与经验标定数据，越做越好。
> 数据出处：6 镜全自动成片实测 7 分 52 秒；旁白精修 + 换 BGM + 重制仅约 2 分钟（复用视频素材）。

## 一、标准作业流程（SOP）

### 0. 环境预检（30 秒）

- `GET /api/health`：确认实例存活；`GET /api/tasks?limit=1` 响应含 `total` 字段 = v2.0+ 新代码。
- `GET /api/settings`：`api_key_set`（必需）、`fish_api_key_set`（配音需要）、`music_api_base`（BGM 需要）。
- `ffmpeg -version` 可用（渲染需要；缺失时渲染请求被 400 拒绝）。
- 默认端口 8273，仅本机回环。

### 1. 创意写作（成片上限在这一步决定）

创意字段是全流程的种子——文案、分镜、角色、场景全部由它派生，写得含糊全线平庸。公式：

> **时空** + **主角（身份 + 1~2 个外观锚点）** + **核心道具/事件** + **情感落点**

实测样本（可直接套用此密度）：
「深夜末班地铁，年迈的清洁工老周在空车厢打扫，在座椅下捡到一块旧怀表，表盖里嵌着泛黄的全家福照片。次日清晨，他在站台长椅上等到哭着回来寻找的小女孩——那是她去世父亲的照片。他把怀表轻轻放回她掌心，晨光第一次洒进站台。」

要点：时空自带转换（深夜→清晨 = 天然冷暖对比，光线叙事白赚）；道具承载情感（怀表+全家福）；落点具体可视（晨光洒进站台，而非"温暖人心"这类抽象词）。

风格字段给三件套：`视觉风格 + 光线 + 镜头质感`，如「电影写实，冷暖对比，浅景深」。

### 2. 模式选择

- **全自动**（新建项目勾选「🚀 全自动成片」）：创意完整、要快速拿到初稿。实测 6 镜 7m52s，瓶颈是视频限流（1 次/分钟 × 镜头数）。**跑完必查**：带角色的镜头是否都有「以 &lt;Picture 1&gt;…」前缀（见避坑 #4）。
- **分步精修**：对分镜/旁白有强控制欲时用；第②步生成分镜后**人工过一遍旁白字数**（≤ 秒数×4）。

### 3. 分层重制策略（重要：坏了不用整体重来）

| 层     | 内容                                       | 重做成本    |
| ------ | ------------------------------------------ | ----------- |
| 剧本层 | 文案 / 分镜 / 旁白                         | 秒级（LLM） |
| 素材层 | 角色图（~22s）/ 镜头视频（限流 1 次/分钟） | 分钟级      |
| 音频层 | 逐镜配音（每条 ~5s）/ BGM 选用             | 秒级        |
| 合成层 | 渲染参数（转场/字幕/音量/预设）            | ~1 分钟     |

实测：旁白精修 + 逐镜重新配音 + 选 BGM + 重渲 ≈ 2 分钟（6 条视频全部复用）。**视频素材是最贵的，能不重拍就不重拍**。

## 二、避坑清单（每条都真实踩过）

1. **中文 JSON 绝不走 PowerShell `curl.exe`**——实测项目名/创意直接乱码（需删库重建）。程序化驱动一律写 Node fetch 脚本（UTF-8 全程无损），速查见第五节。
2. **旁白字数铁律：≤ 镜头秒数 × 4（含标点）**。TTS 实测 4.3~5.2 字/秒；v2.0.3 已在生成端硬约束 + clamp 兜底，但**手动编辑旁白时仍需自查**（前端暂无即时提示，见建议 #2）。
3. **镜头实际时长 ≈ 标称 +3.5%**（5s 标称实测 5.175s）。旁白 + 0.5s 偏移要留余量：配音 ≤ 4×秒数 字 → 时长 + 0.5s < 实际镜头时长。
4. **全自动的 L1 自审只自动采纳中低严重度**：high 级问题（实测：镜头 4 缺「以 &lt;Picture 1&gt; 开头」）会留在分镜里不修 → 该镜角色形象可能与其他镜不一致。全自动跑完**务必逐镜检查角色引用前缀**，缺了就 `PATCH shots/:id` 补前缀（该镜需重拍才生效）。
5. **BGM 按调性选**：治愈→钢琴/轻音乐（实测《夜的钢琴曲五》契合）；热血→摇滚/电子；纪录→轻管弦；口播→低音量 lo-fi。搜索词用「曲风 + 乐器」命中率高；有旁白时确认「旁白闪避」开启。**v2.1 起全自动已按风格自动选曲（默认轻音乐兜底）**，此坑仅手动精修时需要留意。
6. **渲染配方与题材联动**：治愈慢综（dissolve 900ms + 48 号字幕 + BGM 40%）实测与温情叙事高度契合，直接用 P2 预设卡即可，不必手调。
7. **成片尾部有片尾卡（~3.5s 渐黑）**：抽帧预览最后几秒偏黑是正常的，不是渲染失败。
8. **响度不用管**：自动补偿链工作正常（实测 v1 -14.9 / v2 -15.6 LUFS，目标 -16），无需手动调音量参数除非特殊需求。
9. **时间线历史里「角色图已定稿，跳过生成」**：v2.0.3 已修复该文案失真；若再见此文案且确系流水线自生成的图，属于旧代码实例，重启服务。
10. **时长偏差看质检报告**：`duration_deviation_pct` ≤±8% 优秀（实测 v2 +3.4%）；>+10% 说明镜头被拉长或旁白溢出，回查旁白时长。

## 三、成片自检清单（交付前必查）

- [ ] 每镜旁白：`tts.duration + 0.5 ≤ 实际镜头时长`（`GET /api/projects/:id` 比对 tts 与 shots）
- [ ] 带角色的镜头都有「以 &lt;Picture 1&gt;…」前缀（角色一致性）
- [ ] 质检报告：时长偏差 ≤±8%；响度 -16±2 LUFS；`narrated_shots` = 有旁白镜头数；`sub_lines` 符合预期
- [ ] BGM 与调性匹配、有旁白时闪避开启
- [ ] 抽 4~5 帧人肉过画面：开头（3s）/ 中段 / 情感高潮 / 结尾（注意尾部片尾卡偏黑属正常）
- [ ] 听一遍旁白：无截断（每句完整收尾）、无破音

## 四、经验标定数据（实测）

| 项            | 实测值                                                                         | 推论                                   |
| ------------- | ------------------------------------------------------------------------------ | -------------------------------------- |
| TTS 语速      | 4.26~5.16 字/秒（均值 ~4.6，含标点停顿）                                       | 旁白 ≤ 秒数×4 字是安全上限             |
| 镜头时长膨胀  | 标称 5s → 实际 5.175s（+3.5%）                                                 | 紧凑排旁白时别按标称值贴满             |
| 全自动总耗时  | 6 镜 7m52s                                                                     | **≈ 镜头数 × 60s + ~2min**（限流主导） |
| 各阶段耗时    | 文案 8s / 分镜 24s / L1 审查 11s / 角色图 22s / 配音 37s（6 条）/ 渲染 15s     | 除视频外全部 <40s                      |
| L1 审查命中率 | 实测报 3 项：1 项真问题自动修、2 项 high 留人工（其中 1 项确为角色一致性硬伤） | 审查有真价值，high 项必须人工看        |
| 重制成本      | 旁白+配音+BGM+重渲 ≈ 2min（复用视频）                                          | 分层重制是低成本迭代路径               |

## 五、API 程序化创作速查（AI 会话驱动用）

Node fetch 驱动（**勿用 PowerShell curl 传中文**）：

```js
const api = async (method, path, body) => {
  const res = await fetch('http://127.0.0.1:8273' + path, {
    method,
    headers: body ? { 'Content-Type': 'application/json' } : {},
    body: body ? JSON.stringify(body) : undefined,
  });
  const data = await res.json().catch(() => null);
  if (!res.ok) throw new Error(`${method} ${path} → ${res.status}: ${JSON.stringify(data)}`);
  return data;
};
```

创作序列：

```
POST /api/projects                     {name, idea, style, aspect_ratio, seconds}
POST /api/projects/:id/auto            全自动（或分步：/api/llm/script → /api/llm/storyboard）
GET  /api/projects/:id/auto            轮询状态（stage: script→…→done/error）
# 分步精修补充：
POST /api/projects/:id/shots/:sid/videos        逐镜提交
POST /api/tts/generate                          {kind:'shot', shot_id, text, project_id} 逐镜配音
GET  /api/music/search?keyword=                 选曲 → POST /api/projects/:id/bgm
POST /api/projects/:id/render                   {预设配方参数} → GET …/render/jobs 轮询
```

## 六、项目下一步优化建议（按优先级）

> P0 三项已于 v2.1.0 落地（见 CHANGELOG）：全自动 BGM 阶段 / 旁白前端即时反馈 / 渲染前预检面板。以下为剩余项。

### P1（体验完善）

1. **质检报告可视化告警**：quality 超阈值字段渲染成警示色（偏差 >8% 黄 / >15% 红；响度出 -16±2 红），当前是中性徽章不引人注意。
2. **全自动等待时间预估**：wait_videos 阶段显示「预计还需 X 分钟（限流 1 次/分钟，剩 N 镜）」。
3. **L1 审查「采纳全部非 high」快捷键**：手动审查报告页批量采纳（全自动模式已有此行为，手动模式没有）。
4. **机械性 high 问题自动修复**：全自动管道中「缺 &lt;Picture 1&gt; 前缀」这类确定性修复可安全自动应用（前缀注入幂等且机械），主观性 high 才留人工——实测该类问题被正确发现却未修复，导致角色不一致风险留存。

### P2（锦上添花）

5. **旁白编辑→重渲快捷链路**：旁白保存后出现「应用旁白并重渲」按钮（当前需手动走配音+渲染两步）。
6. **成片多版本对比视图**：同项目多次渲染（v1/v2）并排播放对比。
7. **成功案例参数模板化**：把「创意写法 + 风格 + 预设配方」组合存成可复用创作模板（本手册第一节即为第一个模板）。
