## P0 — 解锁"系列化"（不补则剧本被功能反向限制）

### ✅ P0-1 多角色引用（一个项目只能锚一张角色图）—— 已落地 v2.5

- **落地方案**：镜头级 `ref_image_ids`（≤5，省略=全部定稿角色图）+ 定稿改 `append`（追加）+ `pipeline` 多图注入。
- **问题**（原）：视频提交只注入一张角色定稿图，多角色同框/对手戏无法锚定。
- **证据**（原）：`services/pipeline.js` `submitVideoTask()` 取 `projects.selectedImage(p.id, 'character')`，
  且 `selectImage` 语义为"同一 kind 只有一张 selected"。
- **影响**：E02 的"风花＋修鞋匠"只能靠**构图规避**（鞋匠不给正脸/只出镜手部与侧影）+ 文字锚硬撑。
- **实现**：
  1. `select-image` 支持 `append:true`（追加定稿）/ `selected:false`（取消定稿），默认仍为替换（向后兼容）；
  2. 镜头 `ref_image_ids`（本镜出场角色图 id，≤5）——`POST/PATCH /api/projects/:id/shots/:shotId`；
  3. `pipeline` 按镜头选角色，注入多图（Flash 上限 5 张）；前缀自动并列编号，已含 `<Picture N>` 幂等不改写；
  4. 图片任务"首张自动定稿"改为**仅当该 kind 尚无定稿时**（避免多角色下历史图累积）；
  5. 数据层 `shots.ref_image_ids` 迁移 + `projects.selectedImages()` + `imageRowToApi` 统一映射。
- **验证**：e2e 新增多角色用例（多张定稿/取消/精确选取/前缀）+ 单测 99；**实拍**：镜12 绑两张参考图
  生成「風花＋修鞋匠」同框，两人形象与各自种子图一致 ✓。

### ✅ P0-2 跨项目角色资产库（系列的核心资产没有一等公民）—— 已落地 v2.5

- **落地方案**：`settings.character_library`（KV 零新表）+ 收藏/列表/删除 + `POST /api/projects/:id/characters/import`（复制为项目角色图并追加定稿）。
- **实现**：`routes/characters.js`（新）+ 前端「📚 从角色库导入」/「⭐ 收藏到角色库」+ `openModal` 通用弹窗。
- **验证**：端到端冒烟——从 E02 收藏 2 角色 → 新建项目导入 → 批量建 2 镜（含 `ref_image_ids` 精确引用）全通。
- **遗留**：导入时未校验库中图片 URL 可达性（见 P3-2）；系列模板的"新建项目一键套用（含角色导入）"UI 待做（见 P1-1）。

## P2 — 质检与诊断（AI 创作者的结构性补强，本两集暴露最多）

### ⬜ P2-1 渲染质检面板（把这次的诊断脚本产品化）

- **问题**：抽帧、波形、静音检测、流时长对比，全靠临时脚本 + 手工看图；排查"咯噔"花了 7 轮。
- **建议**：渲染任务详情页提供——
  1. **关键帧缩略图**（开头/中段/高潮/结尾，可点开放大）；
  2. **音频波形图 + 开头瞬态检测**（本次实测：E02 BGM 开头 0.25/0.5/0.75s 有 -0.2/-1.9/-13.9dB 爆音）；
  3. **音视频流时长对比**（本次实测：修复前 137.7s 片音频仅 128.4s）；
  4. 通用诊断脚本沉淀为 `tools/audio-check.js` / `tools/video-check.js`（或挂 API）。

### ⬜ P2-2 客观视频指标（补"AI 看得见图、看不了动态"的盲区）

- **问题**：AI 创作者只能抽帧判断静态质量，**运动质量（抖动/闪烁/动作自然度）无法自评**，
  方法论亦要求"运动维度必看视频"——目前全部依赖人工验收。
- **建议**：用 ffmpeg 计算并输出**客观指标**（无需视觉模型）：
  帧间差（运动幅度）、亮度/色彩波动（闪烁）、边缘密度变化（结构稳定性）、静止帧占比；
  提供"可疑镜头"排序（指标越界者优先人工复核）。这能让 AI 先筛、人只看少数。

## P3 — 细节补丁

### ⬜ P3-1 `ambient_volume` 默认值

- 本轮新增（0–1，默认 0=剥离）。建议**默认 0.2** 或写入系列模板——AI 生成的环境声（雨声/海浪）
  能明显提升沉浸感（E02 对比版实测：镜 7 雨巷差异显著、片头卡差异 0、总响度一致）。

### ⬜ P3-2 角色图 remote_url 的长效性

- 视频提交用平台输出 URL（`charImg.remote_url`）。长期连载（数周）后 URL 可能失效。
- 建议：提交前检测可达性 / 本地图片优先重传 / 失效时明确报错并提示重定稿。

### ⬜ P3-3 日文音拍数估算

- 中文旁白有"≤秒数×4"硬约束（服务端拦）；日文配音只能凭经验估（实测 1.83–7.24s 均安全）。
- 建议：按モーラ（音拍）给"≤秒数×7"的估算提示（或 TTS 前预检时长）。

### ⬜ P3-4 逐镜 `offset_ms` 的 API

- 对白镜"贴开口"需要逐镜偏移，目前**无接口**，只能直改 `project_tts`（绕过契约）。
- 建议：`PATCH /api/tts/:id {offset_ms}`（0–3000）。

## 环境与工程

### ⬜ E-1 `npm run dev`（watch + 优雅重启）

- 改渲染代码后必须手动 kill 进程再启动（本机 PowerShell 下 kill 还会让 AI 终端工具报 `ChildProcess.kill` 错）。
- 建议：`npm run dev`（node --watch 或 nodemon）+ 优雅退出；或提供本地重启脚本。

### ⬜ E-2 `tools/` 目录（让脚本成为可复用资产）

- AI 的创作/诊断脚本目前只能放系统临时目录，无法沉淀、无法复用（每集重写）。
- 建议：项目内 `tools/`（或 `scripts/`）承载：分镜批量导入、质检、诊断、一致性校验等脚本。

### ⬜ E-3 "运营操作" API 化

- 复制角色图（P0-2）、设 `offset_ms`（P3-4）目前在直连 SQLite 操作；建议补 API，避免绕契约。

## 沉淀机制（让"复用"不靠人记）

> 实战做法（每集写"制作记录"）有效，但依赖 AI 自觉。建议机制化：

### ⬜ S-1 一致性台账（单一来源）

- 内容：角色图 id ＋ 服色锚文本 ＋ 风格锚 ＋ 用语表（中日）＋ 用过的 BGM/音色 ＋ 各集时长。
- 现状：散落于 `docs/stories/幻灯屋-系列企划.md` 与 `-制作记录.md`；建议抽成独立文件
  （或 JSON / settings），所有集数引用同一份，**防跨集漂移**。

### ⬜ S-2 每集制作档案（自动草稿）

- 渲染完成时自动生成草稿：参数（风格锚/音色/BGM/渲染配方）、规格（镜数/时长/响度/偏差）、
  质检结果、封面、作品目录。人/AI 只需补"复盘与教训"。

### ⬜ S-3 开拍 checklist

- 第 N 集开机前自动列出：本集角色（图是否齐）、场景图、备选 BGM、时长预算、上集钩子承接。

## 附录 B：AI 创作者能力边界备忘（已写入制作记录，此处汇总）

1. **能看图，不能看动态**：静态质量（构图/色彩/一致性）可自评；运动质量（抖动/闪烁/动作）需人工复核；
   客观指标（P2-2）可部分补强。
2. **判型 > 调措辞**：反复失败先判"模型弱项 / prompt 放大 / 锚缺失"，判错型会白重拍。
3. **改构图 > 改措辞**：可数物件、画面内文字、特定时代感＋微情绪——措辞难根治，**换构图/背景虚化/剪影**最有效。
4. **用形式换容错**：赛璐璐/动画 + 单元剧 + 独白叙事 + 少对白，是当前模型下的高胜率组合。
