## P0 — 解锁"系列化"（不补则剧本被功能反向限制）

### ✅ P0-1 多角色引用（一个项目只能锚一张角色图）—— 已落地 v2.5

- **落地方案**：镜头级 `ref_image_ids`（≤5，省略=全部定稿角色图）+ 定稿改 `append`（追加）+ `pipeline` 多图注入。
- **问题**（原）：视频提交只注入一张角色定稿图，多角色同框/对手戏无法锚定。
- **证据**（原）：`services/pipeline.js` `submitVideoTask()` 取 `projects.selectedImage(p.id, 'character')`，
  且 `selectImage` 语义为"同一 kind 只有一张 selected"。
- **影响**：E02 的"风花＋修鞋匠"只能靠**构图规避**（鞋匠不给正脸/只出镜手部与侧影）+ 文字锚硬撑。
- **实现**：
  1. `select-image` 支持 `append:true`（追加定稿）/ `selected:false`（取消定稿），默认仍为替换（向后兼容）；
  2. 镜头 `ref_image_ids`（本镜出场角色图 id，≤5）——`POST/PATCH /api/projects/:id/shots/:shotId`；
  3. `pipeline` 按镜头选角色，注入多图（Flash 上限 5 张）；前缀自动并列编号，已含 `<Picture N>` 幂等不改写；
  4. 图片任务"首张自动定稿"改为**仅当该 kind 尚无定稿时**（避免多角色下历史图累积）；
  5. 数据层 `shots.ref_image_ids` 迁移 + `projects.selectedImages()` + `imageRowToApi` 统一映射。
- **验证**：e2e 新增多角色用例（多张定稿/取消/精确选取/前缀）+ 单测 99；**实拍**：镜12 绑两张参考图
  生成「風花＋修鞋匠」同框，两人形象与各自种子图一致 ✓。

### ✅ P0-2 跨项目角色资产库（系列的核心资产没有一等公民）—— 已落地 v2.5

- **落地方案**：`settings.character_library`（KV 零新表）+ 收藏/列表/删除 + `POST /api/projects/:id/characters/import`（复制为项目角色图并追加定稿）。

## P2 — 质检与诊断（AI 创作者的结构性补强，本两集暴露最多）

### ✅ P2-1 渲染质检面板（把诊断脚本产品化）—— 已落地 v2.5

- **落地**：`GET /api/render/jobs/{id}/inspect`（按需生成缓存：关键帧 4 张 + 音频波形图 + 音视频流时长对比
  - 客观指标 + hints 告警）；前端渲染任务卡「🔍 质检图与指标」弹窗。
- **实测**：E02 成片（#97）22 秒出结果——流差 0（音轨铺满）、亮度波动 16.9、闪烁帧占比 0。
- **意义**：此前每次质检需临时写 ffmpeg 脚本 + 手工看图；现在一键可得，且"音频流 vs 视频流"这类**曾导致尾部静音的隐性缺陷**可直接读数。
- **遗留**：指标为整片粒度（见 P2-2：镜头级指标仍待做）。

### ✅ P2-2 客观视频指标（补"AI 看不了动态"）—— 已落地 v2.5

- **落地**：`lib/video-metrics.js`（共享：`luma_mean`/`luma_std`/`flash_ratio`/`motion_mean`/`sampled_frames`）
  - 成片级（`GET /api/render/jobs/{id}/inspect`）+ **镜头级**（`GET /api/tasks/{id}/metrics`）。
- **实测**：E02 镜4（静镜）18 秒出结果——亮度 86.1 / 波动 0.3 / 闪烁 0 / 运动 0.6，与"老人捧鞋的静态镜"相符。
- **用法**：AI 先按指标筛可疑镜头（`flash_ratio` 高 = 闪烁、`motion_mean` 异常 = 抖动/幻灯片），再交人工复核少数。

### ✅ E-4 素材归档可靠性（弱网不再毁掉渲染）—— 已落地 v2.5

- **修复**：① `workers/render.js` ffmpeg 硬超时 20 分钟（不再永久挂起）；
  ② 卡片背景图先落地到工作目录再交给 ffmpeg（`resolveCardScene` + `materializeImage`，180s + 1 次重试）；
  ③ `workers/image-worker.js` 归档下载 3 次重试（图片侧无补扫兜底，单次失败即永久缺失）。
- **遗留（已清）**：① ~~图片无"补扫"~~ → v2.5.2 已补：`image-worker.sweepArchives()` 按
  `project_images.local_path` 补下载（每进程一次、最多 40 张、逐张 2 次重试），实测首轮把
  **77 张缺备份的项目图片**补齐 19 张（其余为链接已过期的历史项目）；

  "已 N 分钟无进度更新——可能在读取远端素材；超过 20 分钟会自动失败并给出原因"。

### ✅ E-5 提示词机械守卫 + 提交器错误分类 —— 已落地 v2.5.0

- **事故 A（风格漂移）**：人工返工 `PATCH` 整段替换 `video_prompt` 后丢掉风格锚 → 生成结果漂移成写实风格。
  修复：`services/prompts.js` 新增 `ensureStyleAnchor`（幂等），`pipeline.js` 在**两条分支**统一补齐
  （此前纯文生分支提前 `return`，空镜必中）。
- **事故 B（503 秒判死）**：`submitter` 除 429 外一律 `fail`，上游 `video_queue_full`(503) 直接把任务
  打成 `submit_error`（E03 重拍 4 次全被拦）。修复：5xx 与网络错误同档退避重试，失败详情为空时给出可读原因。
- **教训（可复用于任何"机械注入"）**：守卫要加在**所有出口**上（分支 return 是盲区）；
  错误分类要区分"瞬时"与"终端"，否则重试机制形同虚设。

## 附录 B：AI 创作者能力边界备忘（已写入制作记录，此处汇总）

1. **能看图，不能看动态**：静态质量（构图/色彩/一致性）可自评；运动质量（抖动/闪烁/动作）需人工复核；
   客观指标（P2-2）可部分补强。
2. **判型 > 调措辞**：反复失败先判"模型弱项 / prompt 放大 / 锚缺失"，判错型会白重拍。
3. **改构图 > 改措辞**：可数物件、画面内文字、特定时代感＋微情绪——措辞难根治，**换构图/背景虚化/剪影**最有效。
4. **用形式换容错**：赛璐璐/动画 + 单元剧 + 独白叙事 + 少对白，是当前模型下的高胜率组合。
