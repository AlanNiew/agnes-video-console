## 一、平台缺陷（4 个，全部已修 + 已写 CHANGELOG / 单测）

| #   | 现象                                                         | 根因                                                                                                                 | 修复                                                                                                             |
| --- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | 渲染卡在 40% 达 30 分钟，ffmpeg 仅耗 2.9s CPU                | `-loop 1 -i https://…`：卡片需 3.8s×30fps≈**114 帧，每帧重下整图**；且 `runFfmpeg` **无超时**                        | ffmpeg 硬超时 20 分钟；卡片素材**先落地本地**再交给 ffmpeg                                                       |
| 2   | 16 个镜头 `video_local_path` + 主题图 `local_path` 全为 null | 归档下载**单次失败即永久缺失**；图片侧**没有补扫**（视频有 `sweepArchives`）                                         | 图片归档 3 次重试；渲染侧 `resolveCardScene` 兜底；开启 `video_auto_download` + `POST /api/tasks/{id}/poll` 补扫 |
| 3   | 成片 1:10 处风格变成写实（手像真人）                         | 返工 `PATCH` **整段替换 `video_prompt` 丢了风格锚**；且守卫只加在引用角色分支、**纯文生分支提前 return**（空镜必中） | `ensureStyleAnchor` 幂等守卫，两条分支统一补齐（+3 单测）                                                        |
| 4   | 连续 4 次重拍全部 `submit_error`，提示"提交失败（503）："    | 提交器**除 429 外一律秒判死**，上游 `video_queue_full`(503) 直接打死任务                                             | 5xx 与网络错误同档**指数退避重试**；空详情给可读原因                                                             |

### 可复用的工程模式（比单个 bug 值钱，务必记住）

1. **守卫要加在所有出口**——分支 `return` 是盲区（缺陷 3 的直接原因）。
2. **错误必须分「瞬时 / 终端」**——否则重试机制形同虚设（缺陷 4）。
3. **任何"把远端 URL 直接喂给子进程"的地方都是潜在死锁**——统一"**先落地再使用**"（缺陷 1、2）。
4. **静默降级是最贵的 bug**——进度冻住、无报错、不失败，只能靠人眼发现（缺陷 1）。
5. **"库里的值 ≠ 实际发出的值"是漂移温床**——提示词在被注入/拼接后必须可见（本次漂移靠人眼发现）。

## 二、能力缺口（尚未做，按价值排序）

1. **开工预检（preflight）** ⭐：网络/CDN 速率、ffmpeg/ffprobe、代理、API Key、磁盘、单实例锁。
   本批 90% 的痛苦源于"没人告诉我网络只有 48 KB/s"。
2. **风格一致性的机器发现** ⭐：本次漂移由**用户肉眼**发现。应做成"新镜产出 → 与风格锚/已定稿镜比对 → 超标提示重拍"。
3. **提示词最终提交版可见**：shot 应展示注入锚/角色前缀后的**真实 payload 文本**，可 diff。
4. **动态质量报告**：AI 能看静态帧、看不到运动；缺"逐镜抽帧网格 + 时序异常（抖动/形变/闪烁）"自动报告。
5. **发布物料延伸**：竖屏切片（导流）、B 站字幕文件适配、封面文案（现只有文案 + 封面图）。
6. **成本/额度看板**：13 镜 = 13 视频 + 13 TTS + 2 图；无成功率/重试率/耗时分布。
7. **多集编排**：目前一次一集；E05+ 需要"排 N 集"。

## 三、优化点（体验 / 性能）

- **渲染**：① 进度停在 40% 无解释 → **阶段化进度**（"归一化 5/13"）；② **13 镜每次重渲都重跑归一化** → 素材未变应复用（可省近半时间）。
- **提交节流**：1 次/分钟 → 13 镜至少 13 分钟，是单集时间的硬下限。
- **质检**：靠抽样 4 帧/镜 → 应自动出网格报告 + 一键对比。
- **信息重复**：角色库 / 创作模板 / 台账三处重叠；台账应部分由平台生成（现为手写索引）。

## 四、环境与工具（踩坑）

- **网络是第一瓶颈**：TUN 开启前 ≈48 KB/s → 开启后 ≈2 MB/s（**40×**）。开工前必须实测 CDN 速率。
- **服务重启高频且易错**：重启丢 `FISH_PROXY` → TTS 全 502（本批踩到）；单实例锁接管有延迟（"检测到另一实例持有工作锁"→ 30s 后接管）。
- **PowerShell 坑**：中文 JSON 走 curl 乱码；`node -e` 内嵌 ffmpeg 参数被拆错 → **一律写成脚本文件**（已入 `tools/` 规范）。
- **ffmpeg/ffprobe 是硬依赖**：抽帧、时长、响度全依赖它，但仍缺"一键体检"。
